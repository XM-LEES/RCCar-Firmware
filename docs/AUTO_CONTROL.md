# AUTO纵向控制实现说明

本文定义当前`feature/symmetric-speed-control`分支的AUTO软件契约：完整PID、前进主动制动、倒车滑停及模式二换向。`rc-validated-v1`冻结的是已验证RC实现；本分支的AUTO结构已经落入代码，PID增益、B_min和制动时序采用工程初值。

本文规定控制行为，不改变11字节下行和24字节上行的速度、转向语义。已实现的字节接收、幅值换算及RC观测详见[ESC观测与速度发布](ESC_OBSERVATION.md)。

## 1. 动作范围与不变量

| 当前运动及目标 | 执行动作 |
| --- | --- |
| 前进，需要加速或稳速 | PID调节前进推进量 |
| 前进，需要减速 | 先撤销多余推进；根据超速量、滑行进度和预测释放速度决定是否主动刹车 |
| 前进，需要停车 | 在有效前进制动许可下制动到停稳，然后回中 |
| 前进，需要倒车 | 同一次连续足量刹车→确认停稳→回中并确认→倒车推进 |
| 倒车，需要减速 | 减少倒车推进，必要时回中滑行，不输出正向刹车 |
| 倒车，需要停车 | 回中滑停 |
| 倒车，需要前进 | 回中滑停，确认停稳及中位后才允许前进 |

必须满足：

1. **运动方向来自反馈观测，动作许可来自独立协议状态。** 发出推进命令不等于已经沿该方向运动；发出负向PWM也不等于已经刹车。
2. **倒车未停稳时不得输出正向PWM。** 正目标在此期间只形成滑停请求。
3. **一次前进刹车必须作为连续会话处理。** 会话释放后，不因误差变大或滑行超时直接补第二次负向刹车。
4. **速度大小与方向有效性分开。** 控制不以零替代非零的未知方向速度；上行不隐藏方向未知。
5. **PID调节完整输出。** PID在相对中位的完整端点范围内计算；最终PWM由电调输入端点和当前动作许可共同约束。
6. **时间目标不授予动作许可。** 超过减速时间预算可以申请刹车，不能越过未知许可去执行可能成为倒车的负向信号。

回中不等于驻车。倒车滑停的减速率取决于地面、负载和摩擦；该策略不承诺倒车停车时间或坡道驻车能力。

## 2. 输入、状态与参数

### 2.1 输入及符号

| 符号 | 单位 | 定义 |
| --- | --- | --- |
| r | m/s | 当前有效目标；正前进、负倒车；BRAKE命令把r置0 |
| m | m/s | 最新有效ESC速度幅值 |
| D、K | — | 观测方向−1/0/+1及方向可信度 |
| v | m/s | K有效时D×m；精确零RPM可给出零速度；其他未知方向非零幅值不能组成v |
| Z | bool | 多份新鲜低速样本构成的停稳证据 |
| S | — | FE32实际动作：NEUTRAL、DRIVE、BRAKE、UNKNOWN |
| t_rx | ms | 本帧末字节的接收时刻 |
| P0、P_F、P_R | µs | 中位、前进端点、负向端点；P_R<P0<P_F |
| u | µs | 相对中位的有符号控制输出，P=P0+u |
| a | m/s² | 由新鲜有符号速度样本计算的滤波变化率 |
| Δ | m/s | 前进正目标下的超速量v−r |

RC和AUTO使用独立观测实例及动作历史；RC算法和直通输出不因AUTO参数或状态改变。AUTO每次换控制源清许可和PID动态状态，保留本源已建立的中位校准；接管时若仍运动而方向未知，先回中滑停。

r直接取有效命令。目标阶跃由PID和动作阶段响应；制动申请由实测误差、滑行进度和模式二许可决定。

### 2.2 初始配置

以下控制参数是本规范的工程初值，用于确定实现和复现输入；它们不是本车已完成的PID或制动力标定。所有参数均有单位，运行前按数值关系检查，不使用人工valid开关。

| 参数 | 初值 | 用途 |
| --- | --- | --- |
| P0 / P_F / P_R | 1500 / 2000 / 1000µs | 现有接口端点；普通推进、制动和换向资格均在完整物理行程内约束 |
| Kp | 120µs/(m/s) | 参考旧标定映射并提高低速起步余量的工程初值 |
| Ki / Kd | 20 / 0 | I用于消除运动后的稳态误差；D先关闭，待实车响应稳定后再调 |
| τ_a | 80ms | 速度变化率的一阶滤波时间常数 |
| T_aw | 100ms | 积分跟踪实际输出的时间常数 |
| E_on(r) | max(0.20m/s, 0.10×r) | 前进大超速刹车介入界线 |
| E_off(r) | max(0.05m/s, 0.02×r) | 制动释放和滑行完成的误差带 |
| T_eval | 200ms | 小超速先观察滑行进度的时长 |
| T_coast | 600ms | 前进超速滑行的响应预算 |
| a_progress | 0.05m/s² | 判定存在可用滑行减速趋势的界线 |
| T_release | 80ms | 电调释放作用延迟的初始估计，仅用于控制预测 |
| B_min | 50µs | 连续制动命令的最小负向偏移；必须校准到电调中位区之外 |
| T_action_ack | 300ms | 前进刹车请求后的动作一致性检查时间 |
| T_qualify | 100ms | F→R完整负向PWM连续保持时间 |
| T_neutral | 100ms | 换向中位驻留时间 |
| T_fresh / T_command | 250 / 250ms | 沿用反馈、命令新鲜度要求 |
| 停稳阈值/份数/覆盖 | 0.05m/s / 3 / 150ms | 沿用已验证观测的停稳配置 |
| PWM决策/上行周期 | 20 / 50ms | 观测通知不改变正常输出节拍 |

Ki单位为µs/[(m/s)·s]；Kd单位为µs/(m/s²)。参数必须有限，Kp>0、Ki≥0、Kd≥0、τ_a和T_aw>0，0<B_min≤P0−P_R，E_off<E_on，0<T_eval<T_coast，时间均小于u32半回绕范围。

接收时间戳和阶段计时用u32毫秒；速度变化率、积分及预测公式统一用秒。下文τ_a、T_aw参与公式前分别换算为0.080s、0.100s，不把毫秒数直接乘入m/s²。

B_min用于避开电调中位区，不代表物理制动力。若收到的动作不能确认BRAKE，不能把“已发负向PWM”记为“实际刹车已成立”；按第7节处理。

中位及B_min在AUTO已授权或尚未确认停稳时保持上一份有效配置，避免运行中改变连续制动会话的电气区间定义。其他模式二参数变化会使AUTO历史失效并先到物理中位；运行中PID系数的更新按第4.2节处理。

Kp小或Ki过小时，低速目标可能无法克服死区，P控制也可能有稳态误差。不得以“尚未起步”启动固定故障倒计时，也不得偷偷放大目标速度。是否提高Ki或启用D由响应曲线和实车调参决定。

## 3. 观测、执行与上报时序

### 3.1 完整样本与命令上下文

AUTO必须顺序消费完整FE32样本，不能只读取最新帧来判定动作转换。RC与AUTO各自按当前source代号消费，始终只有Servo任务修改运动和动作状态。

每个合法样本至少包含：

```text
sample_id、receive_epoch、delivery_epoch、t_rx
rpm_raw、rpm_valid、state_raw、state_valid
首字节上下文：PWM、source代号、输出用途purpose、动作会话session_id、auto_context
```

purpose取实际已提交输出的用途：RC_DIRECT、NEUTRAL、FORWARD_REQUEST、REVERSE_REQUEST、FORWARD_BRAKE。正负目标、PID计算值或“计划下周期输出”不能直接代替该字段。RC使用第一个上下文字的RC标志入队；AUTO必须在第二个上下文字置`auto_context`，并携带purpose/session。

session_id在source改变或输出用途切换时更新；REVERSE_REQUEST因BRAKE确认升级为FORWARD_BRAKE时，只要负向命令没有中断，保留连续负向会话标识。同一制动会话内力度、停车/换向目的变化不切断会话；满制动资格另记起点。NEUTRAL提交必定结束负向会话。

首字节用途用于排除后续命令对旧反馈的解释；末字节时间用于计算年龄。完整帧跨source则拒绝动作证据。上下文仍是软件命令，不是ESC内部采样时刻；FE32没有可用的执行确认编号，不能声称它证明了ESC在该精确PWM下采样。动作确认、连续输出驻留和多帧停稳共同构成切换条件；T_action_ack、T_release及T_qualify须覆盖实测链路和电调响应，不能只按任务周期估算。

### 3.2 任务分工

1. PD15 ISR仅采集字节及紧凑上下文；解析在任务中进行。
2. 接收任务逐帧校验；RC上下文或显式AUTO上下文进入8项静态FIFO，再发送通知；最新原始快照保留供独立诊断。
3. Servo事件入口按顺序更新动作证据、方向、停稳、PID反馈、a和预测释放计数；批末原子发布最新结果，不执行历史PWM。
4. 每20ms进行一次控制决策：检查授权→读取最新一致观测→选择动作阶段→计算PID与刹车需求→提交一个最终PWM→记录上下文及实际输出。
5. 上行每50ms取最新快照。动作颜色可以降采样；内部动作判断不能以该50ms快照代替完整样本流。

通知不移动控制截止点。实际输出只由Servo任务写入；正常事件处理不额外增加PWM更新次数。源切换、接收失效或FIFO缺口撤销旧会话证据，控制在下一20ms截止点回中；不能静默拼接缺口两侧的BRAKE与DRIVE。串口`ENABLE=0`、`SOFTWARE_STOP`或失效边界至少经过一个物理中位控制周期后才清除该边界的pending状态；后续合法命令不能越过这次中位边界复用旧动作证据。

控制截止点到达时先消费本批反馈，再执行一次当前控制决策；未到截止点的通知仅运行观测和快照发布。若一次处理跨过多个截止点，只执行一次最新决策，并把原截止点按20ms整数倍推进到未来，不回放错过的PWM。每批工作有固定上界，进入下一批之前重新检查截止点。

## 4. 完整PID

纵向控制使用一个有符号PID计算器。前进与倒车使用同一物理速度符号；动作阶段决定输出的合法区间。

### 4.1 变化率

对同一观测阶段的两个不同有效样本：

```text
dt = u32(t_rx[k] - t_rx[k-1]) / 1000
a_raw = (v[k] - v[k-1]) / dt
α = dt / (τ_a + dt)
a[k] = a[k-1] + α × (a_raw - a[k-1])
```

dt必须为正且不超过T_fresh。重复样本不更新；dt=0不做除法；丢帧边界、方向重新确认或时间倒序清变化率历史，第一份新样本令a=0。正常前进推进、滑行和制动之间保持该历史。D对测量求导，目标阶跃不直接形成微分冲击。

### 4.2 控制计算及积分

每个20ms控制时刻：

```text
e = r - v
u_raw = Kp × e + I - Kd × a
u_applied = 当前动作阶段对u_raw的投影及电调端点约束
```

u_applied取最终实际写入的PWM减P0。一次控制周期只使用最新观测计算一次输出，不能按队列里的历史速度补发多次输出。

积分使用前向离散更新，更新值用于下一控制周期：

```text
只有取得新PID反馈样本，才计算dt_pid；重复样本不积分。
若Ki=0：I_next=0；当前工程初值Ki=20，但仍只在取得新PID反馈样本时积分。
若阶段不允许PID调节（滑行、等待、资格刹车、反馈无效）：I_next=0。
否则：
    若目标刚变化，本次不追加Ki×e×dt_pid；P立即响应新目标。
    若输出已在合法上/下边界且e还要求进一步越界，本次不追加误差积分。
    其余情况 ΔI_error=Ki×e×dt_pid。
    β=min(1, dt_pid/T_aw)
    I_next=clip(I + ΔI_error + β×(u_applied-u_raw), -(P0-P_R), P_F-P0)
```

Ki为0时，跟踪项也不能形成隐藏积分。source变化、方向请求变号、软件停止、阶段切换到滑行/等待时清I。正常样本之间保留I。参数修改在控制截止点采用整份配置快照；修改PID系数时清I、D历史和前进刹车预测释放计数，但不清当前运动方向。

不能用未知方向的非零幅值代替v。启动前已确认停稳且最新RPM精确为0时，可用v=0计算首次请求；出现运动但方向尚待确认时，暂持最后一个目标方向一致的启动输出，不累计未知符号误差，见第8节。

### 4.3 输出区间

| 阶段 | 最终PWM |
| --- | --- |
| 前进推进/正常正向恢复 | P0+clip(u_raw,0,P_F−P0) |
| 倒车推进/初始倒车请求 | P0+clip(u_raw,P_R−P0,0) |
| 滑行、等待、未授权 | P0 |
| 前进跟踪/停车制动 | P0−clip(max(B_hold,−u_raw),B_hold,P0−P_R) |
| F→R资格制动 | P_R，完整负向行程 |

PWM最终按1µs量化并写入端点范围；量化后的P用于资格判断。不得用请求力度代替实际输出证据。

## 5. 前进刹车：介入、力度和释放

![前进刹车调度](diagrams/auto-braking.svg)

本节跟踪规则适用于r>0且方向观测为前进。目标0或负值分别进入停车/换向流程，不套用跟踪释放条件。

### 5.1 误差带与预测量

```text
Δ = v - r
E_on = max(0.20, 0.10×r)
E_off = max(0.05, 0.02×r)
age_ms = u32(now_ms - t_rx_ms)
H_s = (age_ms + 20 + T_release_ms) / 1000.0
v_release = max(0, v + a×H_s)
```

E_on/E_off只控制制动模式切换，不修改r，也不把小目标裁剪为零。v_release仅用于预计松刹后的速度，不能替代实际测量、停稳或方向证据。a尚不可用时禁用预测释放，以实测速度条件为准。

### 5.2 撤销推进与立即介入

从推进进入Δ>E_off的减速过程时，先撤销正向推进，清I，开始一个超速滑行计时t_coast。若Δ≥E_on且尚不满足释放条件，申请主动刹车，不等待T_eval。已处于连续制动时执行当前阶段，不重复清I、重启计时或切回滑行。

负向刹车只有前进许可F_READY成立时可执行；否则按第7节恢复规则处理。不得用误差大、计时已到或PID负值绕过该条件。

### 5.3 小超速滑行后的介入

Δ在E_off和E_on之间时允许先滑行。使用新鲜样本估计达到释放误差带所需时间：

```text
若a < -a_progress：T_need_s=(Δ-E_off)/(-a)
否则：T_need_s=正无穷
T_remaining_s=max(0.020,T_coast_ms/1000.0-elapsed_coast_ms/1000.0)
```

满足以下任一项即申请刹车：

- t_coast≥T_eval，Δ>E_off，且T_need_s>T_remaining_s；
- t_coast≥T_coast，且Δ仍>E_off。

仍需通过释放预测和F_READY许可检查。滑行已经足够快且预计能及时进入误差带时，不因“经过200ms”就必然刹车。600ms是推进到制动的调度预算，不是停车故障超时，也不是实际收敛保证。

相同目标的周期性命令不重启t_coast；目标继续减小时也不重启。只有误差回到E_off以内、方向/控制源变化或进入新制动会话才结束该计时。

### 5.4 制动力度

进入允许的制动会话后，正常力度由第4节PID负向需求决定，最小保持偏移B_hold初始为B_min，最大为完整负向端点。

- 大超速使比例项产生更大的负向需求，可使用完整制动行程，不设置低于倒车资格阈值的臆测软上限。
- 超速缩小则减小力度；启用D后，已存在的减速趋势会降低制动需求。
- B_hold取会话开始时已标定的B_min，整个会话保持不变。首份BRAKE仅证明该请求被解释为刹车，不能把当时的较大力度当作最小有效力度，否则会阻止后续减弱制动。
- 只有显式退出会话才输出中位；禁止通过中位脉冲调制平均刹车力度。

B_hold可能使小误差下仍存在最小制动力，因此释放预测和实测释放条件必须优先于“继续保持最小刹车”。B_min及PID系数需要结合响应记录标定；参数初值不等于已测得制动能力。

减弱到B_hold期间若意外收到NEUTRAL，按动作一致性丢失处理；不能自动再加大负向力度重试。一次高力度BRAKE反馈不能证明50µs初值已在中位区之外。

### 5.5 跟踪制动释放

满足任一条件即释放跟踪制动：

1. 实测v≤r+E_off；
2. 连续两份不同的新鲜前进样本均满足a<0且v_release≤r+E_off；
3. 新目标已不需要减速，且PID正常请求正向推进。

两份预测证据必须在同一目标值和TRACK目的下形成；目标数值或制动目的改变时清该计数。重复目标刷新不清计数，重复读取同一反馈不增加计数。滑行计时仍按5.3处理，不能因清预测计数而重启。

释放转入F_RECOVER：若PID本身给出正向推进，则按正常PID输出；否则回中。不能为了恢复刹车许可额外给固定正向油门。停稳、方向未知或反馈异常按更高优先级处理。

一次释放即消耗本会话的前进制动许可。若预测过早、释放后仍超速，又尚未出现正向DRIVE确认，保持回中并报告BRAKE_REARM_REQUIRED，不能自动再踩一次负向信号。正向DRIVE确认后方可重新执行5.2/5.3。

这台模式二电调不能同时保证“任意次数负向刹车、期间始终不正向推进、又绝不误倒车”。本规范保留方向安全约束；若实际任务要求上述能力，需要改变电调模式或增加独立制动执行器，不能用隐藏重试解决。

## 6. 停车与换向

### 6.1 前进停车

r=0且仍在前进、Z尚未成立时，若F_READY有效，直接进入F_BRAKE/STOP，不先等待滑行预算。已有连续制动会话则仅改变目的，不回中重开会话。已经停稳的零目标直接保持中位。

力度按r=0的PID和B_hold计算；近零时保持同一次负向制动直到Z成立，然后回中。跟踪目标的预测释放条件不用于声明停车完成。若许可不完整，则回中并报告许可原因，不能为停车盲目发送第二次负向信号。

STOP目的下，动作开始之后的新样本已建立Z，且当前S为BRAKE或NEUTRAL时，判停车完成并立即回中；不要求一定捕获过BRAKE，也不再因T_action_ack到期报告刹车未确认。此情况只证明停车完成，不授予倒车资格。若出现会话内意外DRIVE或相反运动证据，则先处理动作冲突，不能以低速Z掩盖冲突。

### 6.2 前进转倒车

F_READY有效或当前已处于有效连续前进制动会话时，负目标将该会话升级为REVERSE目的，直接使用P_R。升级期间不得夹入中位。

R_QUERY也有唯一的升级入口：同一source/session的新BRAKE反馈，其首字节上下文确为本次连续负向REVERSE_REQUEST，且其间未提交中位，授予F_BRAKE_ACTIVE并进入REVERSE目的。下一20ms控制截止点写入P_R；此前不能凭负目标或零RPM提前写满刹。升级不宣称D为前进。

同时满足以下证据才建立倒车资格：

- 最终实际PWM连续保持P_R至少T_qualify；中断立即清该保持计时。
- 已收到当前source、当前连续负向会话、且完整负向输出开始之后的BRAKE反馈。
- 停稳证据由完整负向输出开始之后的新样本构成，满足份数及覆盖时长。

首次实际写入P_R时记t_full并清旧停稳累计，T_qualify从t_full计时；需另取得首字节PWM已为P_R的BRAKE样本，查询阶段较弱PWM的BRAKE不能替代这一确认。完整行程确认预算也从t_full开始，取T_action_ack。单纯保持旧的R_QUERY请求不能累计完整行程资格。

然后输出P0，进入R_DWELL。中位持续至少T_neutral、收到本次中位命令之后的新NEUTRAL反馈，且仍保持Z，才允许按负目标PID给出倒车推进。推进发生不直接赋值D=−1，方向仍需DRIVE运动样本确认。

若负目标到来时已有制动会话刚释放，不能补发一次更强负向刹车：已建立完整倒车资格且停稳时可完成中位驻留；资格不完整时先滑停，再走初始倒车请求流程。

### 6.3 倒车减速、停车和转前进

倒车推进只允许P≤P0。较小倒车目标可减少推进；PID要求正向作用或目标0时输出P0。倒车转前进同样先输出P0，收集该滑停阶段的新停稳证据。

Z成立、中位持续T_neutral且NEUTRAL反馈确认后，正目标才进入前进启动。该过程没有正向BRAKE阶段，也不等待BRAKE→DRIVE序列。

### 6.4 制动与驻留期间的目标变化

当前有效目标始终覆盖先前推进意图；完成旧阶段不能恢复已被撤销的目标。以下转移在下一控制截止点执行；RC接管及数据失效的优先级更高。

| 当前阶段 / 新目标 | 转移与证据处理 |
| --- | --- |
| 连续F_BRAKE任一目的 / r<0 | 保持原负向会话；进入REVERSE，首次完整输出后重新收集资格证据。已是REVERSE且仍为负目标，只更新目标幅值，不重启资格计时 |
| F_BRAKE/REVERSE或TRACK / r=0 | 取消倒车意图、清t_full及未完成的倒车资格；连续会话转STOP，按停车条件执行。已停稳则立即回中 |
| F_BRAKE/REVERSE或STOP / r>0，仍确认前进且v>r+E_off | 清倒车资格和预测计数；原会话转TRACK，按新目标的PID力度及释放规则执行，不再保持资格用完整行程 |
| F_BRAKE任一目的 / r>0且无需继续制动 | 释放会话；运动中转F_RECOVER，停稳时经中位确认后正常前进启动。不得为完成旧倒车资格继续满刹 |
| R_DWELL / r<0 | 完成新中位反馈、驻留和停稳条件后按当前负目标启动；负目标数值刷新不重启驻留 |
| R_DWELL / r=0 | 保持中位，取消待执行的倒车推进和保存的倒车资格，转NEUTRAL_WAIT |
| R_DWELL / r>0 | 取消倒车推进及资格；满足停稳与中位确认后进入F_START，不经过R_DRIVE |

由上述取消路径清掉资格后，负目标再次到来时走第8节R_QUERY；不会恢复已取消的REVERSE或R_DWELL。实际电调若已具备倒车条件，查询会由新DRIVE反馈确认。仍在同一次有效连续负向制动内再次转REVERSE，则按新资格起点收集证据，不夹中位重试。

TRACK转STOP或REVERSE时清预测释放计数；STOP的停稳窗口从STOP目的进入起重新收集，REVERSE则从完整输出开始收集。方向未知且出现无法归属的非零运动时，按第9节处理，不能借本表赋予方向。

## 7. 动作许可与制动会话

运动观测保存D/K/Z；动作许可另保存以下状态，不能互相替代：

| 许可 | 建立条件 | 允许行为 |
| --- | --- | --- |
| UNKNOWN | 上电、源切换、证据缺口、异常动作或欠资格会话释放 | 中位；停稳后按第8节启动/查询 |
| F_READY | 新鲜FORWARD_REQUEST上下文的DRIVE，且前进运动已由观测确认 | 正向推进、滑行，以及一次连续前进制动会话 |
| F_BRAKE_ACTIVE | 消耗F_READY进入本次连续负向制动；或第8节倒车请求实际收到BRAKE | 维持本次负向制动及会话内升级，不跨中位重试 |
| R_READY | 第6.2节全部资格及中位条件成立，或已观测到请求中的倒车驱动 | 倒车推进或中位；倒车运动期间禁止正向PWM |

制动首次发出后标记pending，不立即认为ESC已经执行BRAKE。pending期间可以根据先前已确认的前进和F_READY保持原运动方向，但不得把用途为FORWARD_BRAKE的DRIVE样本解释成新的倒车确认。

pending期间的DRIVE/NEUTRAL可属于动作尚未响应的反馈，未出现其他冲突时允许等待至T_action_ack；第一次匹配BRAKE将会话标记为已确认。此后再次出现DRIVE/NEUTRAL才适用下述会话一致性检查。R_QUERY已经收到BRAKE后升级完整行程，不重新获得忽略DRIVE/NEUTRAL的宽限。

T_action_ack内必须收到本次会话对应的新BRAKE；没有确认则输出中位、清该许可并报告BRAKE_NOT_CONFIRMED。该期限只检查电调动作响应，不用于判断低速目标是否已起步。

该计时只在实际提交FORWARD_BRAKE，或首次写入资格P_R时启动；不适用于NEUTRAL_WAIT、正常F_START，或尚未观察到BRAKE的R_QUERY。每个新帧依次判定：失效/用途冲突→会话内意外DRIVE或相反运动→STOP完成→REVERSE资格完成→未主动释放的意外NEUTRAL→动作确认超时。STOP已完成或REVERSE资格已成立时，必须先转入中位阶段，不再使用旧会话的超时/NEUTRAL检查重复报错。

BRAKE已确认后，若在未主动释放的会话里收到NEUTRAL或DRIVE，认为动作一致性丢失：回中，撤销旧许可及无法继续证明的方向，保留可用幅值；不自动加大负向信号再次尝试。首字节记录属于旧会话、但晚交付的帧不能确认新会话；ESC内部测量时延仍按3.1的限制处理。

释放后的F_RECOVER只使用正常正向PID请求恢复F_READY。目标0时保持中位；目标负且仍运动时滑停；不得通过未请求的正向起步来恢复倒车资格。

## 8. 启动、未知状态与方向确认

首次AUTO启动需取得有效中位及新鲜停稳证据。启动时不假定MCU复位等于ESC复位，不直接继承旧动作许可。

- 正目标：给出正常PID正向请求，等待FORWARD_REQUEST上下文的DRIVE及运动证据确认前进。
- 负目标且R_READY成立：给出正常PID负向请求。
- 负目标但许可未知：在停稳和NEUTRAL确认后给出正常PID负向请求，标记R_QUERY。不能把它直接替换为满刹车，也不能先强制前进。
- R_QUERY收到同一连续负向请求的DRIVE及运动证据，按观测规则确认倒车；收到BRAKE则该信号实际处于制动，保持负向会话不中断并升级第6.2节资格流程。
- R_QUERY尚无运动且只收到NEUTRAL时，不因起步慢而猜测许可；PID可按实际零RPM工作，Ki=0时不足以越过死区的输出不会自动被放大。

方向确认采用RC的中位学习、两份初次DRIVE运动样本、BRAKE/NEUTRAL保持已有运动方向等依据，并增加AUTO用途约束：只有FORWARD_REQUEST、REVERSE_REQUEST/R_QUERY上下文的DRIVE能确认相应新方向，刹车请求不能自行证明倒车。

启动中出现非零幅值但方向仍待确认时，不以目标符号给速度强加正负号；暂持最后一个与请求方向一致的启动输出，冻结I，等待有效确认。反向证据、用途冲突、目标0、源/接收缺口均撤销该保持。未超过新鲜度期限且仅缺第二份确认样本，不误报接收故障。

低于运动确认阈值的未知方向启动可能无法形成可信有符号反馈；这属于观测阈值和电机死区的实测调参范围，不能通过伪造方向或强制增大目标掩盖。

## 9. 执行阶段及优先级

| 阶段 | 输出 | 退出条件 |
| --- | --- | --- |
| NEUTRAL_WAIT | 中位，收集新鲜中位/停稳 | 有有效目标且启动条件成立 |
| F_DRIVE / F_START | 正向PID；pending期间按第8节 | 超速→F_COAST/F_BRAKE；零/负目标按对应流程 |
| F_COAST | 中位，运行滑行计时 | Δ≤E_off且有正常正向PID需求→F_DRIVE；满足5.2/5.3且有许可→F_BRAKE；零/负目标按第6节 |
| F_BRAKE（TRACK/STOP/REVERSE） | 按目的执行连续负向输出 | 当前目标优先按6.4转移；目标不变时TRACK释放→F_RECOVER，STOP停稳→中位，REVERSE资格成立→R_DWELL |
| F_RECOVER | 正常正向PID或中位，不发负向刹车 | 新正向DRIVE确认→F_READY；负/零目标按第6/8节 |
| R_DWELL | 中位 | 仅当前目标仍为负且中位驻留、反馈确认及停稳均成立→R_DRIVE；目标0或正按6.4取消旧倒车意图 |
| R_QUERY / R_START | 正常负向PID；不得盲目满刹 | DRIVE确认→R_DRIVE；BRAKE确认→连续资格制动 |
| R_DRIVE | 负向PID或中位 | 需要滑停/正目标→R_COAST |
| R_COAST | 中位 | 同向负目标可按已知R许可恢复推进；正目标须停稳和中位确认 |

每个控制周期按以下优先级选择一条路径：

1. RC取得控制权：退出AUTO输出，保持RC既有行为。
2. SOFTWARE_STOP、关闭ENABLE、命令陈旧或不可用反馈：中位，清AUTO动态证据。BRAKE标志属于受控停车，不与SOFTWARE_STOP混同。
3. 方向未知且非零运动无法归属，或观测动作与会话冲突：中位等待新的可用证据。明确例外仅有两类：第8节具有匹配purpose/session、只等待初次方向确认的启动可暂持上次请求；R_QUERY已由匹配BRAKE确认并升级的连续资格制动可按第6.2节继续。两个例外均不能跨越接收/source缺口，也不能给未知速度伪加方向。
4. 倒车尚未停稳：只允许倒车推进或中位。
5. 当前有连续制动或换向驻留：执行该阶段并处理目标变化，不先运行通用正负PWM映射。
6. 其余按目标和超速条件进入推进、滑行或首次制动。

相同目标刷新只更新命令年龄；不能重置制动、滑行或驻留计时。改变目标必须立即参与决策，但不能把“目标变号”作为已换向证据。

每20ms重复写入同一用途和PWM，不重置会话起点、t_full、停稳样本窗口或中位驻留起点。这些起点仅在相应阶段进入、首次完整行程输出或证据失效时改变。

## 10. 失效、恢复和上行

RX错误、FIFO缺口、时间倒序、过期RPM或无效参数使AUTO输出中位，清I/D和受影响的动作证据。数据恢复后重新取得中位与停稳，再按当前有效目标启动；不存在靠CLEAR_FAULT强行赋予倒车许可的路径。

倒车滑停较慢、低速P控制未起步、正常空闲100ms采样间隔不构成上述失效。滑行预算到期只申请制动，不锁故障、不改目标、不设置额外限速。

字节7–8继续发布观测速度；未知方向发布正幅值并清bit23；停稳按现有bit12规则发布零。字节1的ESC动作仍来自FE32，不以控制意图替换。Hall仍为独立测速对照，不进入主PID反馈。

AUTO内部诊断必须能区分：PID原始输出、实际PWM、当前阶段、许可、目的、BRAKE是否确认、会话id、滑行时间、预测释放速度、制动资格、中位确认，以及BRAKE_REARM_REQUIRED等禁止原因。这些首先作为内部状态，不挤占速度/转向字段。

24字节诊断位在本设计中的解释：bit25为AUTO控制条件允许，bit26为PID正在实际调节推进/跟踪制动，bit27为前进跟踪制动阶段，bit28为有效倒车资格，bit29为许可/动作确认不完整，bit30为AUTO请求受条件禁止，bit31为完整PID及非对称门控配置有效。诊断更新不得改变速度与转向的单位、偏移和符号含义。

## 11. 性能与内存契约

- 使用单一Servo状态所有者；一个FIFO顺序消费者，不为RC和AUTO建立两个竞争取帧任务。
- 所有帧、上下文及控制状态静态分配；一批最多处理入口已有的8帧，不能无限追赶生产者。
- 速度换算常量在配置更新时预计算；a滤波使用乘加和一次比例计算，不做历史窗口拟合。
- 运行期PID、a及预测使用单精度浮点和明确单位；不在20ms路径中做参数搜索、堆分配或文本格式化。保留有限值检查，不用激进浮点编译选项破坏无效数判定。
- PID每20ms计算一次；观测逐帧更新；积分仅在新PID样本时更新。重复上行、重复通知不增加积分或确认次数。
- purpose/session元数据使用第二个32位上下文字；两个字的命令上下文采用双缓冲加单字发布索引。单一任务先准备非活动槽，再在同一个短PRIMASK临界区写入实际CCR并提交槽索引；ISR先固定读取索引再拷贝该槽。在本单核、任务写入/ISR读取模型下，ISR期间写入任务不能继续修改已发布槽；禁止引入第二写入者或省略发布顺序。ISR只做常数次读取和入环，不计算PID或状态机。
- 大结构快照及FIFO原子提交沿用BASEPRI优先级保护，PD15优先级3采样保持可响应；位采样关键路径不调用RTOS。
- 正常PWM仍为20ms决策，上行仍为50ms。接收至观测发布年龄、队列峰值、丢弃原因、批次周期数和控制迟到均保留可读诊断。

性能验收要求正常接收负载下无FIFO溢出、通知不移动20ms截止点、队列处理不补发历史输出。实际最大耗时由板上周期计数确认；桌面运行时间不能代替MCU时间保证。

| 制动释放后仍超速，未出现正向DRIVE | 回中、报告BRAKE_REARM_REQUIRED，不能再发负向刹车 |
| 前进停车接近零但Z未成立 | 同一次负向会话保持B_hold；不把预测零速当停稳 |
| STOP已取得动作之后的Z，当前NEUTRAL，未捕获BRAKE | 停车完成并回中；不报BRAKE_NOT_CONFIRMED，也不授予R_READY |
| 初次启动的第一份运动DRIVE，方向尚待第二份确认 | 用途/会话匹配且无冲突时暂持上次同向启动输出；不积分，不因K暂为0立即中断确认 |
| 制动中目标由正改负 | 不回中，升级完整负向；重新建立完整行程之后的资格与停稳证据 |
| 倒车−1→−0.2m/s | P控制u为正，但该方向不允许主动正向刹车，因此最终中位 |
| 倒车−1→0或+1m/s | 中位滑停；正目标须Z及中位确认后才能输出正向PWM |
| 未知状态请求倒车且ESC已可倒车 | 正常负向PID请求→DRIVE运动反馈→确认倒车，不先强制前进 |
| 未知状态请求倒车而ESC报告BRAKE | 保持原负向会话，升级完整资格制动，不夹中位后再试一脚 |
| R_QUERY较弱负向PWM收到BRAKE后升级 | 下一控制截止点首次写P_R才启动完整行程计时、清旧停稳；需新P_R上下文的BRAKE及新停稳证据 |
| 资格刹车或驻留期间目标改变 | 取消不再需要的推进目标，清PID积累；新命令不能继承失效会话资格 |
| 已输出资格P_R但资格未完成，目标改0或正 | 0转连续STOP至停稳；正目标只在仍前进超速时转TRACK，否则释放；均不继续旧倒车资格流程 |
| R_DWELL期间目标改正，尚未倒车推进 | 保持中位至停稳和中位确认，然后F_START；不输出旧目标的倒车PWM |
| 当前工程初值 Ki=20、Kd=0 | I只在新反馈样本上更新，D不参与输出；不得保留实际输出跟踪产生的隐藏I |
| 控制器饱和或门控回中 | 只用实际输出进行积分处理；解除门控后不能释放积压积分形成大输出 |

实车评价分别记录：起步延迟、目标变化幅度、刹车开始/释放时刻、超调或低于目标的幅度、进入并保持误差带所需时间、稳态误差及指令/观测方向一致性。RC已通过的序列作为回归基线；新增AUTO不能仅凭主机算例宣称实车已正确。
