# 接口约束

下行不变；上行保留固定标识 `0xA1`，保持 24B 帧长、偏移、大端与 XOR 校验，字节 3–6 按用户要求从 Hall 计数增量改为下位机计算的 Hall 速度。ESC 主速度字段不变。固件与 Dashboard 必须同步使用这套字段语义。

## 命令：11B，大端

| 字节 | 类型 / 值 | 含义 |
| --- | --- | --- |
| 0 / 10 | `7B` / `7D` | 帧头 / 帧尾 |
| 1 / 2 | `01` / u8 | Ackermann 命令 / flags |
| 3–4 | i16 | 速度，mm/s；正前进、负倒车 |
| 5–6 | i16 | 等效前轮转角，mrad；正左、负右 |
| 7–8 | `00 00` | 保留 |
| 9 | u8 | 字节 0…8 的 XOR |

flags：`01 ENABLE`、`02 BRAKE`、`04 CLEAR_FAULT`、`80 SOFTWARE_STOP`。未知位、非零保留字节或错误校验使整帧无效，无效帧不刷新命令年龄。

ENABLE 关闭时取消串口自动输出，该源取得输出权时置中。ENABLE 开启、控制条件有效且串口源取得输出权时，BRAKE 将速度目标置零，并通过模式二执行受控停车。SOFTWARE_STOP 覆盖串口控制路径：该路径取得输出权时将 ESC、舵机置中；后续合法命令可撤销该位，不要求 CLEAR_FAULT 解锁。RC 停止与接管的优先级保持基线语义。

RC 接管期间，非零串口目标被替换为零目标更新；释放后不执行缓存的非零目标。

CLEAR_FAULT 仅在以下条件同时满足时登记：速度和转角均为零、未置 SOFTWARE_STOP、`ENABLE=0` 或 `BRAKE=1`、RC 停止和 RC 接管均未激活。处理时清除 Hall／通信历史诊断并重算故障源；只有现存故障源消失，才清除 FAULT_LATCHED。该位不是无条件恢复运动的许可。

命令帧由串口任务解析后写入Servo mailbox。Servo任务在下一个20ms控制截止点消费，命令时间戳保留串口接收时刻；命令是否超时按接收时刻判定，不因延后消费而刷新。

定义依据：[命令解析](../WHEELTEC_APP/SerialControl_task.c)、[Servo命令mailbox](../WHEELTEC_APP/servo_basic_control.c)。

## 状态：24B，大端

| 字节 | 类型 / 值 | 含义 |
| --- | --- | --- |
| 0 / 23 | `7B` / `7D` | 帧头 / 帧尾 |
| 1 / 2 | u8 / u8 | 状态与ESC动作 / 帧序号 |
| 3–6 | i32 | Hall 速度，mm/s；由相邻 HallB 脉冲周期计算，符号按控制方向估计；无效填 0，必须结合 bit 13/19 |
| 7–8 | i16 | ESC 车速，mm/s；方向已知时为有符号速度，bit 23 清零时为正的速度幅值 |
| 9–10 | i16 | 从输出 PWM 与标定反算的前轮角，mrad |
| 11–12 | i16 | `v × tan(前轮角) / 轴距`，mrad/s；低速与小转角置零条件沿用基线 |
| 13–14 / 15–16 | u16 / u16 | 板载 ADC 电池电压，mV / 回传周期间隔，ms |
| 17–20 | u32 | status_bits |
| 21 / 22 | `A1` / u8 | 协议标识 / 字节 0…21 的 XOR |

字节1的bit 0…5依次为AUTO_ENABLED、RC_OVERRIDE_ACTIVE、STOP_OVERRIDE_ACTIVE、COMMAND_TIMEOUT、BRAKE_ACTIVE、FAULT_LATCHED；bit 7…6编码ESC动作：`00 UNKNOWN`、`01 NEUTRAL`、`10 DRIVE`、`11 BRAKE`。原STEERING_IS_MEASURED标志取消；无轮角传感器，status_bits bit9仍保持0。AUTO_ENABLED不表示车辆已经运动，BRAKE_ACTIVE只表示串口刹车请求。

| status_bits | 语义 |
| --- | --- |
| 0 / 1 / 3 / 4 / 5 | 故障锁存 / 命令超时 / 停止覆盖 / 刹车请求 / 自动使能 |
| 2 / 10 | RC 接管 / RC 输入故障；保留既有诊断 |
| 6 / 12 | ESC 速度幅值有效 / ESC 停稳推定；互斥 |
| 7 | Hall 短脉冲历史诊断，可随清故障请求清除 |
| 8 / 9 / 11 | 转角估计有效 / 转角实测（0）/ ADC 电压有效 |
| 14 / 15 / 16 / 17 | 最终推进PWM或PID输出饱和 / 转角限幅 / 预留的加速度限制标志（当前保持0）/ 转角变化率限幅 |
| 18 | 自上次清故障以来的 UART4 错帧记录 |
| 13 | Hall 有符号速度有效；与 bit 19 互斥，与 ESC 有效性无关 |
| 19 | Hall 无脉冲推定停稳；Hall 速度填 0，清 bit 13 |
| 20 | 收到新鲜且 CRC 正确的 FE32 样本；使用独立诊断超时，不依赖速度标定 |
| 21 | 新鲜 FE32 样本中的 raw RPM 字段有效 |
| 22 | 低档轮轴实测系数、轮胎半径和新鲜度配置有效 |
| 23 | 车辆方向已知；置位时字节 7–8 的正负号可信，清零时只能解释绝对值 |
| 24 | PD15 软件 UART 自启动以来记录过接收错误 |
| 25 | 自动推进条件已全部满足；包含AUTO使能、新鲜ESC反馈、纵向PID和模式二配置，不表示PWM已经离开中位 |
| 26 | 自动速度闭环正在运行；AUTO授权且当前输出阶段正在使用PID推进或跟踪制动 |
| 27 | 纵向控制器当前请求跟踪刹车 |
| 28 | 模式二已具备有效倒车许可`R_READY` |
| 29 | 模式二许可或动作确认不完整：启动查询、等待停稳/中位、刹车重授权等 |
| 30 | AUTO已请求，但配置、反馈、命令新鲜度或模式二状态禁止常规推进 |
| 31 | 完整PID及非对称模式二门控配置有效；按u32无符号位解释 |

bit 6 / 12 的历史名称带 HALL，其判定来源现为 ESC。bit 6 只表示速度幅值有效，方向可信度由 bit 23 单独给出：方向未知时仍上传正幅值，角速度填零；方向已知时前进为正、后退为负。无效车速与角速度填零并清除对应有效性，不能将无效零值解释为停稳。ESC 电压、电流、温度和原始 RPM 保留为内部独立遥测，不替换已有字段。

Hall速度采用原有周期法：`v = (0.23 × π / 10) / 相邻有效脉冲间隔秒数`。方向并非传感器独立实测。RC下Hall和ESC共用一个运动方向：制动开始时PWM即使已经换边、FE32仍短暂报告旧DRIVE，也继续保留原方向；BRAKE与NEUTRAL同样保留原方向。只有看到非DRIVE动作后的新DRIVE才切换方向。换向后Hall等待新脉冲对。方向未知时Hall速度无效并填0，不能把无效零解释为停稳。

已确认停稳时优先置 bit 12、清 bit 6，上行车速和角速度置零；内部仍保留停稳阈值以内的低速估计。状态帧序号只计数发送帧，不表示电调产生了新的测量样本。

定义依据：[状态封装与 ADC 换算](../WHEELTEC_APP/data_task.c)。

## ESC 遥测

当前代码使用PD15接收电调编程口信号。PD15没有UART RX复用，因此由下降沿EXTI检出起始位、TIM5以84 MHz时基在115200/8N1位中心采样；半位处先复核起始位，完整字节进入固定环形缓冲，再由任务层喂给FE32解析器。半位处已回高表示伪起始位，只累计过滤次数并立即重新监听，不清环形缓冲、接收epoch或bit24；停止位低、采样迟到和缓冲溢出仍是致命错误。TIM5与EXTI中断不调用HAL定时器回调或FreeRTOS API。2026-09-18实测A3持续产生FE/NE，同一电调编程口经USB-TTL直读无错误，因此运行时不再初始化USART2、PA3和DMA1 Stream5。

接入采用 UART 115200 / 8N1、32B FE32 帧，仅读取。帧头 `FE 01 00 03 30`；字节 30–31 为前 30 字节的 CRC16/MODBUS，小端，初值 `FFFF`、反射多项式 `A001`。2026-09-18 对同一台电调分别采集前进、后退各250帧：RPM均为无符号幅值，byte11在两个方向均恒为1。结合动态循环记录，byte11的0/1/2分别表示NEUTRAL/DRIVE/BRAKE。它提供动作状态，但仍不直接提供方向。

| 字节 | 解码 |
| --- | --- |
| 9 / 10 / 11 | 请求油门 / 实际油门 / 原始动作状态；0=NEUTRAL、1=DRIVE、2=BRAKE，状态不作为正反方向位 |
| 13–14 | 小端 u16 × 10 → eRPM 幅值 |
| 15–16 / 17–18 | 小端 u16 × 0.1 → V / A |
| 19 / 21 | ESC 温度 / 电机温度，°C |

`FFFF` / `FF` 表示相应字段无效。每份遥测携带有效性、样本标识、接收时间、receive epoch和接收时的软件PWM上下文。晚处理不能使旧数据变新；上下文描述字节到达C63A时的固件输出环境，不是ESC内部采样时刻。帧定义参考 [MAX5 G2 Plus](https://github.com/JumpMaster/Hobbywing2CRSF)、[MAX4 HV](https://github.com/plc2man/hobbywing-ezrun-max4-hv-telemetry-protocol)、[XR8 / XR10](https://github.com/EclipseVision/HWTelemetry)；这些型号的资料不等同于本车 MAX5 HV G2 的实测结果。

控制权与观测分开：AUTO、经过C63A的RC或外部接收机直控都不影响FE32和RPM幅值的接收。RC运动方向只服务有符号速度和Hall，不写入AUTO方向状态。RC和AUTO都按FE32观测FIFO顺序处理当前source的样本；AUTO样本必须带显式purpose/session元数据。AUTO门控直接消费FE32动作：F→R保留足量刹车、停稳和回中规则；R→F采用中位滑停、停稳和中位确认后再前进。外部接收机直接控制电调而C63A不知道实际PWM时，bit23保持清零，车速字段只能提供正幅值。

主速度幅值不再等待未知极对数和拆分齿比：`轮轴RPM = rpm_raw × 0.14115`，`速度 = 轮轴RPM × 2π × 轮胎半径 / 60`。0.14115来自低档ESC/Hall配对拟合；现有轮胎半径为115 mm。该观测换算有效不等于自动推进获准，后者继续要求停稳与模式二配置。

## 执行器与采集

AUTO推进使用完整PID输出，当前工程初值`Kp/Ki/Kd=120/20/0`，参数仍需实车标定。模式二门控把PID输出投影到当前动作合法区间：前进推进为1500…2000 µs，倒车推进为1000…1500 µs，前进跟踪/停车刹车为1500以下并至少离开中位50 µs，F→R资格制动使用1000 µs完整负向端点。RC油门通过输入有效性与毛刺确认后保留接收机完整行程，不套用自动推进端点。未知状态下的启动输出保持方向未知，直至该输出之后的新鲜运动样本确认方向；机械响应不设固定完成超时。

Hall沿用B通道计数、脉冲周期测速和短脉冲诊断，上行回传独立Hall速度用于对比，不参与ESC主速度闭环。RC下Hall和ESC使用同一已确认方向；AUTO下Hall符号仍跟随现有模式二方向源。实物确认PD14未接线，因此固件不配置TIM4 CH3，也没有guard/AUX接口或状态。PD3拨动开关选择OLED运行/诊断页；两页都固定显示实际电调PWM `E`和转向PWM `S`，不依赖页面切换才能观察执行器输出。
